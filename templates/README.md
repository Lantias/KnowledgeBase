# Documentation Templates

This folder contains templates for creating consistent, high-quality documentation across the Knowledge Base.

## Available Templates

- **[Guide Template](guide-template.md)** - For step-by-step how-to guides
- **[Tutorial Template](tutorial-template.md)** - For learning-oriented lessons  
- **[Reference Template](reference-template.md)** - For technical specifications
- **[Troubleshooting Template](troubleshooting-template.md)** - For problem-solving guides

## Using Templates

1. **Copy the appropriate template** to your target location
2. **Rename the file** to match your content (use kebab-case)
3. **Fill in the template sections** with your content
4. **Update the metadata** at the top of the file
5. **Delete any sections** you don't need
6. **Follow the [contributing guidelines](../docs/guides/contributing.md)**

## Template Structure

All templates include:
- **Metadata section** with tags and categories
- **Clear headings** and structure
- **Placeholder content** showing what goes where
- **Example formatting** for consistency
- **Related links section** for cross-references

## When to Use Each Template

### Guide Template
- **Purpose**: Solve a specific problem
- **Format**: Step-by-step instructions
- **Audience**: Users who know what they want to accomplish
- **Example**: "How to Configure SSL Certificates"

### Tutorial Template  
- **Purpose**: Teach concepts through practice
- **Format**: Learning-oriented lessons with exercises
- **Audience**: Users learning new skills
- **Example**: "Building Your First API Integration"

### Reference Template
- **Purpose**: Provide technical specifications
- **Format**: Comprehensive technical details
- **Audience**: Developers and technical users
- **Example**: "REST API Reference"

### Troubleshooting Template
- **Purpose**: Solve problems and errors
- **Format**: Symptoms, causes, and solutions
- **Audience**: Users facing specific issues
- **Example**: "Resolving Database Connection Errors"

## Customization Guidelines

### Required Elements
- Title and metadata
- Clear structure with headings
- Examples or code snippets
- Related documentation links

### Optional Elements
- Prerequisites section
- Troubleshooting section
- Additional resources
- Version history

### Consistency Standards
- Use consistent heading levels (H1 for title, H2 for main sections)
- Include code examples in appropriate language blocks
- Use the same metadata format across all documents
- Follow the established emoji conventions
